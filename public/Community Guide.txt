Contributing to BookBack

BookBack is a tool for the commons, built by the commons.

---

HOW TO ADD YOUR LIBRARY

BookBack uses a template-based approach. Each library is stored as a URL
template with {{query}} as a placeholder for the search term.

Option 1: The Easy Way (via the Options Page)

1. Open the BookBack options page (click the toolbar icon).
2. Go to your library's website and search for the book "Dune".
3. Copy the URL of the results page.
4. Paste it into BookBack and click "Create Connection".
   BookBack will replace "Dune" with {{query}} automatically.
5. Done. Your library is connected.

Option 2: Manual Template (also via the Options Page)

Click "Add Manual Template" to add a blank row. Edit the URL directly,
replacing your search term with {{query}}.

Example:
  https://catalog.mylibrary.org/search?q={{query}}

Option 3: The Developer Way (Pull Request)

If your library's catalog isn't working with the auto-detect flow, open
an issue or submit a pull request.

To open an issue, go to the Issues tab on GitHub and provide:
  - Library name and homepage (e.g. https://example-library.org)
  - A search result URL: search for any book on the catalog and paste the URL.

Pull requests are also welcome. Areas where contributions are especially
appreciated:
  - Additional retailer/bookseller support (new match patterns in manifest.json
    and selector strategies in strategies.js)
  - Bug fixes for title/author extraction on specific sites
  - Documentation improvements

---

WHY ISN'T THIS AUTOMATIC?

BookBack has no central server or cloud database. It lives entirely on your
device. Library templates are stored locally and never transmitted anywhere.
This means the community curates templates together in the code — we cannot
push silent updates.

---

ARCHITECTURE OVERVIEW (for developers)

Content-script pipeline loaded in order on matched retailer pages:

1. strategies.js   — detects book pages, extracts title/author/ISBN
2. ui.js           — builds and injects the widget, constructs search queries
3. content.js      — orchestrator: SPA detection, debounced MutationObserver

background.js (service worker) — receives the library list and query from the
widget, substitutes {{query}} into each template URL, and opens tabs.

options.html / options.js — the settings page and toolbar popup. Library
templates are saved to chrome.storage.local under the key "libraries".
